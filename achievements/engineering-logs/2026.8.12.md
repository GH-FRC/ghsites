# 2026.8.12

## English

### Goals for the Day

- Create a skin-independent achievement module with a small framework integration interface.
- Unlock one achievement for a first visit and one achievement after every marked website section has been viewed.
- Pair every notification with its sound and retain blocked notifications until audio becomes available.
- Persist achievement progress and ensure that each achievement is presented only once.
- Reproduce the layout and timing principles of the standard Steam desktop achievement notification without copying Steam assets or audio.

### Completed Work

- Added the independent `@gh-frc/achievements` workspace for achievement rules, persistence, section tracking, notification sequencing, UI, and sound.
- Implemented stable internal achievement identifiers while leaving achievement names and descriptions unset.
- Stored unlocked, presented, pending, and visited-section state through a versioned `localStorage` record with safe in-memory fallback behavior.
- Added an `IntersectionObserver` tracker that derives the complete-browsing requirement from every unique `data-achievement-section` marker and preserves partial progress across visits.
- Ensured that the first-visit achievement is attempted immediately and remains pending when browser audio restrictions prevent its paired sound from starting.
- Added a serial notification queue that preserves unlock order, presents each achievement once, and waits for one notification to finish before starting the next.
- Built a skin-independent bottom-right notification with a neutral placeholder icon, the fixed `成就已解锁` message, a 350 ms entrance, a 6 second visible period, and a 350 ms exit.
- Created an original ascending two-note Web Audio chime and exposed a replaceable `AchievementSoundPlayer` interface without using Steam audio assets.
- Added cross-tab-safe append-only progress facts, serialized presentation coordination, and storage-event synchronization so simultaneous page instances cannot erase progress or present the same achievement twice.
- Made repeated initialization in one document share a reference-counted session and made cleanup idempotent.
- Prevented autoplay attempts from remaining permanently blocked by retrying sound preparation directly from eligible activation events, even when an earlier attempt is still pending.
- Added twenty behavior tests covering sound-notification pairing, pending and blocked audio recovery, browser capability fallback, persistence, concurrent page instances, duplicate initialization, complete browsing, repeat visits, cross-page queue handoff, future marked sections, queue timing, malformed storage, unavailable storage, cleanup, and the UI content contract.
- Verified the blocked-audio recovery path, all-nine-section completion, one-time repeat-visit behavior, notification geometry, and error-free execution in isolated Google Chrome sessions.

## 中文

### 当日目标

- 创建不依赖皮肤、仅通过小型框架接入接口运行的成就系统模块。
- 为首次访问和浏览全部标记区域分别解锁一个成就。
- 保证每条通知都与声音配对，并在音频受阻时保留通知，直到声音可以播放。
- 持久化保存成就进度，并确保每个成就只成功展示一次。
- 在不复制 Steam 素材或音频的前提下，参考普通 Steam 桌面成就通知的布局与时序原则。

### 当日完成

- 新增独立的 `@gh-frc/achievements` workspace，集中保存成就规则、持久化、区域追踪、通知排序、UI 和声音。
- 在成就名称和描述保持未确定的同时，加入稳定的内部成就标识符。
- 通过带版本号的 `localStorage` 记录保存已解锁、已展示、待处理和已浏览区域状态，并在存储不可用时安全回退到内存。
- 新增 `IntersectionObserver` 追踪器，从每个唯一的 `data-achievement-section` 标记动态生成完整浏览要求，并跨访问保留部分进度。
- 保证首次访问成就会立即尝试播放；当浏览器音频限制阻止配对声音开始时，成就会继续保持待处理状态。
- 新增串行通知队列，保持解锁顺序、确保每个成就只展示一次，并在上一条通知结束后才开始下一条。
- 完成不依赖皮肤的右下角通知，包含中性占位图标、固定的“成就已解锁”文字、350 毫秒进入动画、6 秒完整停留和 350 毫秒退出动画。
- 创建原创的上行双音 Web Audio 提示，并公开可替换的 `AchievementSoundPlayer` interface，没有使用 Steam 音频素材。
- 新增跨标签页安全的只增不减进度事实、串行展示协调和 storage event 同步，避免同时打开的页面实例覆盖进度或重复展示同一成就。
- 让同一 document 中的重复初始化共享带引用计数的 session，并让资源清理保持幂等。
- 即使较早的自动播放尝试仍处于等待状态，也会直接通过符合条件的用户操作重新准备声音，避免通知永久受阻。
- 新增 20 项行为测试，覆盖声音与通知配对、等待中与受阻音频恢复、浏览器能力回退、持久化、并发页面实例、重复初始化、完整浏览、重复访问、跨页面队列交接、未来标记区域、通知队列时序、损坏存储、存储不可用、资源清理和 UI 内容约定。
- 在隔离的 Google Chrome session 中验证受阻音频恢复、全部 9 个区域的完整浏览、重复访问仅展示一次、通知几何尺寸和无错误运行。

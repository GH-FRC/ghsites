# 2026.8.12

## English

### Goals for the Day

- Allow one public framework to run with either replaceable example content or GHFRC's separate private content.
- Prevent a build from mixing files from public and private content sources.
- Keep the header visible during navigation-triggered scrolling so visitors can select consecutive sections.
- Add responsive phone and iPad layouts while preserving the established desktop framework whenever space allows.
- Make the compact navigation accessible by touch, pointer, keyboard, and touch-style scrolling.

### Completed Work

- Updated framework content loading to prefer an explicitly configured content directory, then the sibling private content repository, and finally the public example content.
- Kept the selected YAML configuration and media files bound to one complete content source.
- Updated media staging to read the Logo path from the selected content configuration instead of requiring one brand-specific filename.
- Updated the implementation specification to distinguish the public placeholder Logo from the unchanged private original.
- Distinguished navigation-triggered scrolling from deliberate user scrolling so the header remains available for consecutive section selections.
- Added a DOM behavior test covering downward section navigation while the header was previously hidden.
- Added DOM behavior tests for keyboard and pointer input taking control during navigation-triggered scrolling.
- Added a DOM behavior test for pressing another header section link before the current navigation scroll finishes.
- Added a `980 px / 981 px` navigation breakpoint, a compressed horizontal-navigation range, and a compact header with the menu button on the left and proportional Logo on the right.
- Applied navigation-structure and responsive-behavior principles from the official Apple, FRC Team 4414, FRC Team 1690, 光华剑桥, and 光华教育集团 websites without copying their brand visuals.
- Added a single-column responsive content flow with text before media, tablet item grids, phone item stacks, proportional media constraints, and a `320 px` minimum supported width.
- Added compact-menu state handling for the toggle button, section links, Logo, outside clicks, `Esc`, resize, wheel input, accumulated touch-style scrolling, and keyboard scrolling inside the menu.
- Limited the compact menu to part of the viewport and preserved internal scrolling when all eight navigation items do not fit.
- Expanded the interaction suite from 9 to 20 passing tests and completed Astro checks, production builds with private and public content, and browser-level viewport measurements.

- 在导航触发的滚动期间保持标题栏可见，使访客能够连续选择栏目。
- 在空间允许时保留既有电脑端框架，同时加入手机和 iPad 响应式布局。
- 让紧凑导航支持触控、指针、键盘和触摸式滚动操作。

- 更新框架内容读取逻辑，依次优先使用明确配置的内容目录、同级私有内容仓库和公开示例内容。
- 保证 YAML 配置和媒体文件始终来自同一套完整内容来源。
- 更新媒体暂存逻辑，改为从选定的内容配置中读取 Logo 路径，不再要求使用特定品牌文件名。
- 更新实施规格，明确区分公开占位 Logo 与未改动的私有原始 Logo。
- 区分导航触发的滚动与用户主动滚动，使标题栏在连续选择栏目时保持可用。
- 新增 DOM 行为测试，覆盖标题栏原先处于隐藏状态时向下进行栏目导航的情况。
- 新增 DOM 行为测试，覆盖导航触发滚动期间键盘和指针输入接管滚动的情况。

- 将紧凑菜单限制在部分视口高度，并在 8 个导航项目无法全部显示时保留内部滚动。
- 将交互测试从 9 项扩展至 20 项并全部通过，同时完成 Astro 检查、私有与公开内容的正式构建和浏览器级视口测量。

# GHFRC 官网响应式布局规格

## 1. 目标

在不改变现有黑白框架、内容接口或皮肤边界的前提下，使 GHFRC 官网能够在手机、iPad 和电脑浏览器中完整浏览与操作。

本功能按照可用屏幕宽度决定导航形式，不按照具体设备名称或操作系统判断。

## 2. 响应式导航

- 宽度不小于 `1101 px` 时，使用横向导航栏。
- `1101–1180 px` 之间压缩 Logo 显示宽度、导航间距、导航字号和页面边距。
- 宽度不大于 `1100 px` 时，使用紧凑标题栏和向下展开的菜单。
- 紧凑标题栏左侧为保持原始宽高比的 Logo，右侧依次提供语言切换、深色／浅色切换和菜单按钮。
- 紧凑菜单从标题栏下方展开，不推动页面内容，也不覆盖整个屏幕。
- 菜单高度受当前视口限制；内容过高时允许在菜单内部滚动。
- 每个菜单栏目至少提供 `44 × 44 px` 的有效触控区域。
- 点击菜单栏目后打开对应的独立页面；当前页面栏目使用加粗和下划线标识。
- 点击标题栏外部或按 `Esc` 收起菜单；使用 `Esc` 时焦点返回菜单按钮。
- 页面向下滚动时先收起菜单，越过标题栏范围后隐藏标题栏；向上滚动时恢复标题栏。
- 在菜单内部滚动不会关闭菜单或隐藏标题栏。

## 3. 内容重排

- 宽度不大于 `1100 px` 时，页面首屏、机器人海报、赛事海报和详情页的主要双栏内容改为单栏。
- 单栏顺序由对应的框架页面类型统一定义，内容文件只能选择预定义类型，不能自行定义布局规则。
- 宽度不大于 `700 px` 时，标题、正文、媒体高度、页面留白和多列内容进一步适配手机宽度。
- 宽度不大于 `600 px` 时，页面左右留白收窄；宽度不大于 `360 px` 时再次收窄，并限制 Logo 显示宽度。
- 常规图片和视频允许在固定媒体框架中使用 `object-fit: cover` 等比裁切，不拉伸源文件；合作机构 Logo 使用 `object-fit: contain` 完整显示。
- 所有媒体均不得产生横向溢出，源文件不因响应式显示而被修改。
- 页面最小支持宽度为 `320 px`。

## 4. 视觉与模块边界

- 当前使用默认黑白皮肤，并支持跟随系统的深色／浅色模式；手动选择只影响当前页面，刷新或打开其他页面后重新跟随系统。
- 本版已加入简体中文与英文语言切换，不加入正式皮肤切换或粒子效果。
- 响应式结构与交互由 `framework/` 管理，视觉数值通过 `skins/` 的设计令牌提供。
- 响应式实现不修改公开示例内容、GHFRC 私有内容或任何源媒体文件。

## 6. 验收标准

1. `320–430 px` 的手机宽度使用紧凑导航且页面无横向溢出。
2. `744–834 px` 的 iPad 竖屏宽度使用紧凑导航。
3. `1024 px` 的 iPad 横屏使用紧凑导航；宽度不小于 `1101 px` 的电脑或较宽平板使用横向导航。
4. 宽度 `1100 px` 使用紧凑导航，宽度 `1101 px` 使用横向导航。
5. 紧凑菜单位于标题栏下方，只覆盖页面上方的一部分内容。
6. Logo 位于紧凑标题栏左侧并保持原始宽高比，菜单按钮位于最右侧；菜单按钮、语言按钮与深色／浅色按钮的有效触控区域均不小于 `44 × 44 px`。
7. 点击 8 个栏目均能打开对应的独立页面，并在菜单中显示当前页面状态。
8. 点击外部、按 `Esc`、向下滚动和向上滚动的行为符合本规格。
9. 手动切换深色／浅色后刷新页面，网站重新跟随系统设置。
10. 自动化测试、Astro 检查以及公开和私有静态构建均能通过。

# 2026.8.13

## English

### Goals for the Day

- Keep the `stable` and `preview` branches on the public placeholder Logo by default.
- Prevent a nearby private content repository from silently changing the Logo used by a public build.
- Publish the first stable GHFRC website build to a temporary Cloudflare Pages address.
- Keep the public framework and private real content separate throughout the deployment process.
- Prepare least-privilege automatic deployment without releasing unfinished feature branches.
- Require Pull Requests and successful automated checks before the public `stable` branch can change.

### Completed Work

- Changed the default content source to the repository's public `content` folder.
- Kept `GH_FRC_CONTENT_DIR` as the explicit path for trusted builds that require private content.
- Confirmed that the staged and built public header image is the byte-identical `content/media/images/placeholder-logo.png` file.
- Prepared the same public-content behavior for both `stable` and `preview`.
- Renamed the public and private development branches to `preview` and their production branches to `stable`.
- Created the `ghfrc` Cloudflare Pages project with `stable` as its production branch.
- Built the website from clean public and private `stable` snapshots using Node.js `24.14.0`.
- Confirmed that Astro reported no errors or warnings, all 9 automated tests passed, and the build used the verified private Logo.
- Confirmed that the generated deployment output excluded the private Git LFS UI reference video.
- Published and verified the stable website at `https://ghfrc.pages.dev` with an HTTP `200` response.
- Added an isolated automatic deployment workflow that reads both `stable` repositories and uploads only generated static output to Cloudflare Pages.
- Stored the Cloudflare account identifier and the 90-day, Pages-only API Token as GitHub Actions repository Secrets in the private content repository.
- Kept the unfinished light and dark mode changes outside the stable deployment release.
- Updated the public repository documentation to use the current `preview` and `stable` branch names and to describe the deployment boundary.
- Added the `Stable pull request checks` workflow for Pull Requests targeting `stable`, covering Astro validation, all automated tests, the production build, and internal-media exclusion.
- Documented the Pull Request and automated-check requirement for public stable releases.
